- **volleyd: a finished wave releases itself on one `release_go`.** The release playbook gains `{{version}}`, `{{date}}` and friends, a `ship` phase that runs after the owner's go, and a `release_pr` fact. volleyd resolves the release version from the newest tag and the change fragments (minor on any `added` or `removed`, else patch; `release_version:` in the wave file overrides it), waits for the release PR's CI, squash-merges it on `go` (deleting the release branch, never `--admin`), closes the wave's issues at once, runs the ship stages at the merge commit, then completes the wave. A release stage's agent is adopted again after a volleyd restart, so a `deploy` stage can restart volleyd. This repository ships its own `.volley/release.yaml` (bump, release PR, tag, `volley deploy`) and `scripts/release-version.ts` (`bun run release:version --set <v>`, `--check`). (#609)
- **volley-desk: the release train shows its version, the release PR and the ship stages.** (#609)
- **volley-issues: the wave helper says when a repository has no release playbook.** The skill's release-branch merge is the train's on one `release_go`, by hand only without a playbook. (#609)
