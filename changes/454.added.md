- **volleyd: agents on the supervisor's own machine run in tmux when cmux is not there.**
  The new `fleet.local_terminal` (`cmux` | `tmux`; unset: `cmux` on macOS when cmux is
  installed, else `tmux`) picks the local host: `local-tmux` starts each agent in a detached
  session `volley-<wave>-<task>-<role>` on your default tmux server (`tmux attach -t <it>` shows
  it), with the same screen, keys, typed text, resize (the Desk's Terminal popout resizes it),
  retire and cleanup as cmux. The fence admits local tmux only for those session names and
  shapes, the launch only with the worktree's sealed `launch.sh`, and killing a session only
  with consent. `agent_spawned` carries `terminal`; `volleyd cleanup` closes each workspace in
  the terminal its agent ran in. A launch where tmux is missing fails with the line to install
  it. Read at start: a change applies at the next start. (#454)
- **volley-cli: `volley setup` gains a Terminal step.** Between Accounts and Services, it picks
  the terminal volleyd starts local agents in: cmux on a Mac that has it (with the socket-mode
  check that used to run in Services), else tmux, blocking with the install line (`brew install
  tmux`, `sudo apt-get install -y tmux`, `sudo dnf install -y tmux`) while tmux is missing; Linux
  never hears of cmux. The choice goes in `config.yaml` (`fleet.local_terminal`) and `setup.json`
  (`terminal`), and `volley setup --check` prints one row per step, Terminal included. The
  volleyd systemd unit gets `KillMode=process`, so restarting volleyd leaves its tmux agents
  running. (#454)
