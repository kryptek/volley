- **volley-cli: `volley setup` ends with a 1-issue test wave.** The new last step, `first-wave`, asks
  once ("Run a 1-issue test wave now?", Enter: yes; never under `--yes`, `--simulated`,
  `--no-first-wave` or `--check`), creates a scratch private repository `volley-hello-<4>`, files
  "Add HELLO.md", pushes `release/<date>-hello`, adds it to the fleet with `volley repo add … --wait`,
  writes `.volley/waves/hello.yaml` (`pipeline: [implement, merge_ready]`, `merge: auto`), submits it
  with `volleyd run … --owner <coordinator>` and follows the wave until volleyd merged its PR (the
  URL and the wall time; on a failure the journal's tail and the open decisions; 15 minutes at
  most). `--repo <path> [--issue <n>]` runs it on a clone of yours; `--simulated` against
  volley-sim's fakes. `setup-metrics.json` records `first_wave: { wall_ms, pr, merged }`, the
  `Setup complete` line reports it, and the end prints `gh repo delete <owner>/<name> --yes`.
- volleyd: the default model lives in one place, `DEFAULT_MODEL` in `config-defaults.ts`; the
  test wave, the `/volley-issues` skill and the README cite it.
