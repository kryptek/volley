- **volley-cli, volleyd: peer readiness no longer keeps a stale doctor result until the service
  restarts.** `volley peer run` re-runs the doctor on the next heartbeat when the volley
  checkout's `package.json`, `bun.lock` or install marker changes, or when `volley peer doctor`
  ran (it writes `~/.volley/peer-doctor-ran`), and re-reads the versions it reports; `volley peer
  doctor --fix` prints `readiness republished` once the service's record carries the new run,
  else how to restart the service (and says it could not check when the broker refuses it). A
  Repair (`peer_doctor`) folds its report into the box's retained machine record and readiness
  verdict at once, and the box's next heartbeat, still carrying its service's older run, no
  longer undoes it. A doctor report's `doctor_at` is now when its run started, so a run that
  began before a fix never reads as one after it, and runs are compared as instants. A Repair on
  a box whose tunnel is down leaves its record as it is. (#320)
